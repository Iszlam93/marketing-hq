02Five rules to set before agents go team-wide

1
Set limits before the spend, not reports after itA dashboard tells you last month's bill. A limit stops this month's.
With Kimchi: budgets per team, developer and agent. Requests stop at the limit.
2
Limit per team and per agent, not one company capOne shared cap punishes the teams that use AI well, and hides the one runaway agent.
With Kimchi: separate limits for each team, each developer and each agent key.
3
Pay frontier prices only for frontier workGartner's advice: small models for routine tasks, frontier models for hard ones.
With Kimchi: each task goes to the right model; Claude or OpenAI run on your own key.
4
Decide where the code goes, and who holds the keysYour security team will ask both questions before the rollout, not after.
With Kimchi: Kimchi's cloud or yours. Agents never see your credentials.
5
Measure cost per merged pull request, not per seatA seat tells you who has access. Cost per merged PR tells you what the money bought.
With Kimchi: what every merged PR cost, by team, with Claude Code usage in the same view.
